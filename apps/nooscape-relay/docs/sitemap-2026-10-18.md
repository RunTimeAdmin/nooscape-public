# The sitemap (2026-10-18)

`https://nooscape.si/sitemap.xml` is what a search engine is told to read. `robots.txt` names it. Until 2026-10-18 it was a static file of 11 pages. It is now built by the server from three lists.

## What it lists

| List | Where it comes from | Why |
|---|---|---|
| The fixed pages | `client/public/sitemap.xml`, copied by the build | The routes that ask to be indexed. |
| The Owl's Catch days | `readCatchArchive` (`server/owlsCatch.ts`), newest first, at most 100 | Each `/catch/<date>` page has its own head and asks to be indexed. |
| The reviewed records | `listLiveAtlasRecords` (`server/db.ts`), the records the public reads serve, withdrawals out | A reviewed record has its evidence, and its page asks to be indexed (`server/routeHead.ts`). |

It does not list the acknowledged directory entries (about a quarter of a million thin pages, each `noindex, follow`), the operator page, the 404 page, or the scaffold pages behind a feature switch.

The five fixed pages that were missing, `/field`, `/about`, `/changes`, `/sources` and `/context`, are in the file now. No decision had left them out.

## How it is made

`server/sitemap.ts`, mounted in `server/_core/vite.ts` before the static files (which would send the fixed pages alone). The two database lists are each read at most every ten minutes, the answer carries a one hour cache header, and a list that cannot be read keeps the last good one (or is empty) and logs one line. A database that is down never turns the sitemap into an error: the fixed pages are still sent with a 200. If the file of fixed pages is missing, the request falls through as it did before.

## What a test holds

`server/sitemap.test.ts`:

- Every fixed page is on the site's origin, a route the app draws, listed once, and asks to be indexed (its head has no robots rule of its own, or it is the home page or the catch archive, which keep their own heads).
- **Every route that asks to be indexed is listed**, so a page added to the app fails the test until it is in the file. Removing one page from the file fails it (checked).
- The file lists no `/agents`, `/catch/<date>`, scaffold or admin address.
- The lists the server adds, their cache, the last-good behaviour, the circuit-open case that is not logged, and the HTTP answer (GET, HEAD, the content type and cache header, the database down, the file missing).
- The route is mounted before the static files, the records come from the served reviewed set and never the directory's entries, and `robots.txt` names the sitemap.

## Submitting it to Google

Search Console takes the address, not a file: add the property for `nooscape.si`, then Sitemaps, then enter `sitemap.xml` and submit. Ownership is proved by a DNS record (a domain property) or by a file or tag on the site (a URL-prefix property). The sitemap tells Google where to look. It does not make Google index anything, and the acknowledged entries stay out of search by their own head.
