# Decision record: taking payment on Base, settled by Coinbase

**Decided:** 2026-10-21, by the operator, in chat. After the directory survey (the402.dev, Agent402, x402 List) showed that no directory reads Arc,
he said "maybe we need to add base and solana x402 methods for us", then "build base, i want to get on coinbase bazaar", then "ARC and BASE
address is the same receiving". Solana was not built: the reason is in [the record](../x402-base-bazaar-2026-10-21.md).
**Changes:** pay per call takes USDC on Base beside Arc, at the same prices, to the same address. A Base payment is settled by Coinbase's CDP
facilitator, with a token made from a CDP API key. The 402 lists Base first. It is off until `CDP_API_KEY_ID` and `CDP_API_KEY_SECRET` are set.
**Does not change:** what an answer says, a record, a score, a tier, an evidence level, the Arc terms and their settlement through Circle, a caller
with a key, the free limit, the database (no migration), or the price.

## What the operator is asked to approve

1. **Coinbase as a second processor of a payment.** On Base, our server sends Coinbase the signed transfer (the payer's wallet address, the
   amount and the signature), as it sends Circle's the Arc one. The Privacy page now says so, and says Coinbase lists the API in its public
   catalogue, the Bazaar, which shows how many payments and how many different payers it had.
2. **A Coinbase account and a key on the server.** A CDP Secret API key (the operator creates it) is held in the host's environment. It signs
   requests to the facilitator and nothing else here. It is an API credential and not a wallet key: moving funds out of a CDP wallet needs a
   separate wallet secret, which this server does not hold. It should still be made with the narrowest permissions the portal offers. Coinbase's facilitator is free for the first 1,000 settlements a month and $0.001 after, and after that its
   account needs a payment method (until then a settlement answered "payment method required" is shown to a caller as the service being
   unavailable, with nothing charged).
3. **The wording** of the Terms ("on the Arc network or, where the API offers it, on Base"), the Privacy page (the facilitator sentence) and
   the developer page. They are one separate commit and can be changed or dropped without touching the code.
4. **The first live payment,** $0.01 on Base from a wallet that is not the receiving address, run by the operator with a script that refuses to
   sign anything but the Base terms to the receiving address. That payment is what puts the route in the Bazaar.
5. **Base first** in the 402 (below).

## What I chose, so he can say no

1. **Base before Arc.** The validator Coinbase runs reads the first terms, and a client that takes the first terms it can sign pays there. A
   buyer with Arc USDC only and such a client would sign for Base and fail. Arc first would keep the 402 as it was for the Circle marketplace
   review, and Coinbase's validator would say `valid: false`.
2. **Coinbase settles Base, not Circle,** because only a Coinbase settlement is catalogued. Circle also settles Base and would have been the
   smaller change.
3. **Regular wallets only on Base.** The node that checks a contract wallet is Arc's.
4. **Base is offered only with Arc on mainnet,** and a half-set or wrong Base setting turns Base off and never Arc.
5. **No output example in the Bazaar block.** Coinbase advises one for ranking. It would add about 600 bytes to the header, carried three times.
6. **A payment whose answer is lost stays open** (Coinbase has no idempotency key, so a second send of a settled payment is refused). The caller
   is told to check their wallet and to quote the payment id if the USDC left it; the operator sees the payment on the payments page, with the first transaction
   it named, and looks the transfer up. The wait for Coinbase's answer is 40 seconds.
7. **Coinbase's answers are sorted by whose problem they are,** from its troubleshooting reference: the payer's are refused, ours (our terms, metadata, account or
   server location) are shown as unavailable and left open for the operator, and anything that can hide a transfer stays open. A first live payment that is refused
   as unavailable means a problem of ours, and the server log names it.

## What stays for later, and for the operator

- Solana, and the other networks Coinbase settles. Base smart-contract wallets. A Base node to watch for reorganizations. The output example.
- A paid call at least every 30 days keeps the route listed; nothing here makes one.
- To switch Base off: remove the two settings and deploy.
